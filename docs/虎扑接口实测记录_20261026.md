## 五、★ 选手评分接口（2026-10-26 20:20 已锁定，免登录）

**你提供的评分页**：`https://m.hupu.com/score/detail.html?outBizType=lol_item&outBizNo=79822`

页面本身只是 11 KB 的 React SPA 壳（`bbs-genericscore-opg`），数据靠 axios 拉。
从 `detail.a649f23a.js` 里挖出了 axios 实例配置：

```js
// prod 环境
axios.create({ baseURL: "https://games.mobileapi.hupu.com", withCredentials: true })
// 浏览器环境会由拦截器补上 /<pad>/<appVersion>
baseURL += "/" + (isPad ? 4 : 1) + "/" + (HupuBridge?.nainfo?.version ?? "8.2.99")
```

### 5.1 实际可用的 base

```
https://games.mobileapi.hupu.com/1/8.2.99/bplcommentapi
```

### 5.2 两个端点

**(A) 反查节点（选手 → 所属局）**

```
GET /bpl/score_tree/getSelfByBizKey?outBizType={type}&outBizNo={no}
```

返回 `data.nodeId`、`data.linkNodes[]`，其中含父级节点，例如：

```jsonc
"linkNodes": [{
  "level": 2, "desc": "第1局", "target": "PARENT",
  "outBizKey": { "outBizType": "lol_bo", "outBizNo": "7717", "key": "lol_bo:7717" }
}]
```

**(B) 取子节点评分（局 → 全阵容）**

```
GET /bpl/score_tree/getCurAndSubNodeByBizKey
    ?relation=CHILD&page=1&pageSize=30&outBizType=lol_bo&outBizNo=7717
```

实测返回 `code:1`、`data.pageResult.data[]` 共 **24 条**，其中：

### 5.3 字段映射

| 需求 | 接口字段 | 说明 |
|---|---|---|
| 选手名 | `node.name` | 「教练 Helper」这种名字含前缀 |
| 分数 | `node.scoreAvg` | 0~10，一位小数 |
| 打分人数 | `node.scorePersonCount` | |
| 总分 | `node.totalScore` | |
| 阵营 | `infoJson.teamId[0]` | 2 = iG、100193 = HLE（按场次变化） |
| 类别 | `infoJson.type[0]` | player / coach / bpHero |
| KDA | `infoJson.killCount/deathCount/assistCount[0]` | 均为单元素数组 |
| 头像 | `node.image[0]` | |
| 分布 | `node.scoreDistribution` | `{"2":21762,"4":661,"6":188,"8":108,"10":885}` |
| 热评 | `node.hottestComments` | **字符串数组**（不是对象） |

**注意**：`infoJson` 里所有值都是**单元素数组**，取 `[0]`；`label` 字段是渲染样式 JSON，不是位置文本。

### 5.4 完整解析链路

```
评分页 URL
  → outBizType=lol_item & outBizNo=79822
  → (A) getSelfByBizKey  → linkNodes 里找到 lol_bo:7717
  → (B) getCurAndSubNodeByBizKey(lol_bo:7717)
  → 24 条节点 → 按 infoJson.type 过滤 player/coach → 按 teamId 分组
```

选手级节点 `subNodeCount = 0`（没有子节点），所以必须走「先反查局、再取子节点」。

所以「帖子 → 比赛 → 评分」的自动关联需要**赛程接口**，目前未找到：

| `https://m.hupu.com/match` | 404 |
| `https://m.hupu.com/esports` | 404 |

**过渡方案（已实现）**：App 内提供「粘贴评分页链接」入口 → 解析 → 展示全阵容评分。

## 六、★ 赛程接口（2026-10-26 21:20 打通）

### 6.1 树结构与关键结论

```
lol:1（根：英雄联盟赛事，nodeId=1458935，subNodeCount=0）
└── lol_match（比赛，如 "HLE 0-1 IG"，bizId=4513）
    └── lol_bo（第1局，bizId=7717）
        └── lol_item（选手/教练/BP英雄/解说，bizId=79822）
```

向上取父节点：
```
GET /bpl/score_tree/getCurAndSubNodeByBizKey?relation=PARENT&outBizType=lol_match&outBizNo=4513
→ pageResult.data[0].node = 「英雄联盟赛事」 lol:1
```

**但根节点没有子节点**：
- `getCurAndSubNodeByBizKey(relation=CHILD, lol:1)` → `pageResult` 空、`totalCount=0`
- `groupAndSubNodes(nodeId=1458935)` → `nodePageResult.totalCount=0`
- `getSubGroups(outBizType=lol&outBizNo=1)` → `data={}`
- `lol_competition` / `lol_season` / `lol_tournament` + `competitionType=130159678583195` / `competitionStageType=110469977` → **全部不存在**

⇒ **无法通过父节点列出比赛**，只能按 `bizId` 枚举。

### 6.2 编号规律：赛事内连续

实测扫描（`getSelfByBizKey?outBizType=lol_match`）：

| bizId | 比赛 | 赛事 | 状态 |
|---|---|---|---|
| 4501–4516 | 全部有效，共 **16 场连续** | 全球总决赛 | COMPLETED |
| 4500 / 4517 | 空 | — | — |
| 3400 | KT 2-0 KRX | LCK联赛 | COMPLETED |
| 2800 | G2 1-0 FUR | 电竞世界杯 | COMPLETED |
| 2000 / 1200 / 600 / 100 | 空 | — | — |

**⇒ 同一赛事内 id 连续，赛事之间有空档（可能是几百到上千）。**

### 6.3 单场字段（detail.infoJson）

| 需求 | 字段 |
|---|---|
| 队名 | `homeTeamName[0]` / `awayTeamName[0]` |
| 比分 | `homeTeamScore[0]` / `awayTeamScore[0]` |
| 队标 | `homeTeamLogo[0]` / `awayTeamLogo[0]` |
| 赛事名 | `competitionTypeCn[0]`（如「全球总决赛」） |
| 阶段 | `competitionStageTypeCn[0]` |
| 比赛时间 | `matchTime[0]`（unix 秒） |
| 状态 | `matchStatus[0]`（COMPLETED / …） |
| 胜方 | `winTeamId[0]`（与 homeTeamId / awayTeamId 比较） |
| 官方 match id | `matchId[0]` |

### 6.4 App 采用的发现策略（`HupuMatchService.discover`）

```
1. 锚点（默认 4516，最新一场）有效 → 直接用
   无效 → 上下各按步长 8 粗扫 10 轮，找任一可用锚点
2. 从锚点向两侧逐号探测
3. 单向连续 3 次未命中即停（单向上限 40 次）
4. 按 matchTime 倒序返回
```

**已知局限**：跨赛事空档较大时，粗扫可能找不到下一个区块（step=8 会跳过窄区块）。
后续若要更稳，可改为「记录上次的 maxId 到本地，下次从该点向上探」。

### 6.5 局列表与选手评分

```
GET /bpl/score_tree/getCurAndSubNodeByBizKey?relation=CHILD&outBizType=lol_match&outBizNo=4513
→ 局列表（lol_bo，name 如「第1局」）

GET /bpl/score_tree/getCurAndSubNodeByBizKey?relation=CHILD&outBizType=lol_bo&outBizNo=7717
→ 选手/教练评分（同第五节的 24 条结构）
```

### 6.6 坑：成功码是 1，不是 200

`games.mobileapi.hupu.com/bplcommentapi/*` 成功返回 `{"code":1,"msg":"成功"}`，失败为 `code:-1`；
而 `bbs.hupu.com/api/v2/*` 用的是 `code:200`。
`HupuClient.getJson` 因此增加 `okCodes` 参数（默认 `{200}`，评分/赛程调用传 `{1}`）。

## 七、评论接口（2026-10-26 21:45 打通）

```
GET /bplcommentapi/bpl/comment/list
    ?outBizType=lol_item&outBizNo=79822&publishTime=0&order=HOT&page=1&pageSize=20
```

**参数**（缺一个就报错，报错信息会明确点名缺哪个字段）：

| 参数 | 说明 |
|---|---|
| `outBizType` / `outBizNo` | 评分对象；**只有 `lol_item`（选手）有数据** |
| `publishTime` | 必填，传 `0` 即可（传节点发布时间也行） |
| `order` | 必填，界面上的「最亮/最晚/最早」；传 `HOT` / `NEW` 均可 |
| `page` / `pageSize` | 分页 |
| `cursor` | 响应里带，可用于游标翻页 |

**响应**：`data.comments[]` / `data.commentCount` / `data.hasMore` / `data.cursor`

**评论字段**（节选）：

| 字段 | 说明 |
|---|---|
| `commentUserName` / `commentUserHeadImg` | 用户名 / 头像 |
| `commentContent` | 正文 |
| `commentContentImages` | 配图，可能为 null / 字符串数组 / 对象数组 |
| `commentDate` | 「20小时前」这类相对时间 |
| `lightCount` | 亮数 |
| `score` | 该用户给这个选手打的分（0 = 未打分） |
| `ipLocation` | 省份 |
| `commentOccasionText` | 例如「发布于比赛中」 |
| `subCommentCount` | 子回复数 |

### 7.1 关键结论：评论挂在选手上，不在比赛上

| 节点 | commentCount |
|---|---|
| `lol_match:4513`（比赛） | **0** |
| `lol_bo:7717`（第1局） | **0** |
| `lol_item:79822`（Gumayusi） | **4688** |

⇒「每场比赛的评论」实际要按**选手**拉取值，App 里做成「点选手卡片 → 弹出评论区」。

### 7.2 队伍 id → 队名

选手节点的 `infoJson.teamId` 是虎扑内部队伍 id（如 `137`、`1693079573970944`），
**没有队名字段**。队名要从**比赛节点**的 `homeTeamId/homeTeamName`、`awayTeamId/awayTeamName` 映射：

```dart
if (teamId == match.homeTeamId) name = match.homeTeam;
else if (teamId == match.awayTeamId) name = match.awayTeam;
```
